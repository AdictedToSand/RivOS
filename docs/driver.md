# RivOS Drivers

RivOS drivers are provided by RivOS in the initramfs, to have modules while defining a simple API.

## IMPORTANT

This currently is not stable and bound to make breaking changes.

## How to create one?

A RivOS driver most importantly, should be placed somewhere in 

/drv/type/name.drv

Type can be:
    - fs
    - storage
    - More will be added later.

A .drv file is a directory. It should contain:

* (/ = $PROJ_ROOT)
    - /conf.cfg
    - /executable somewhere (fp is defined in .cfg). This should be a static executable.
    - /Other files if needed. NOTE: Can not write files while in initramfs which is a known and by design limitation.
    - /fn.rap This will define a list of functions this driver exposes in a .rap format. E.G.
        open(str fp )=3221225472
        NOTE: This is also how you get the function address. DO NOT STUB.

* /conf.cfg and /executable are the only required files. Other files are completely optional. In this doc, we will not talk about the raw /conf.cfg, but the conf.cfg used in the [../initramfs/src](initramfs/src) directory. It will be relatively similar to the raw /conf.cfg but specify other things (like sourcefiles). The raw /conf.cfg spec may be added later, however is not recommended to be used

* There is no automatic initialization program. It is recommended to simply check a 'isInitialized' flag.

~~~ini
[gen]
# This should be either fs or storage (for now!)  
# drvType="type"
drvType="fs"
# Name of the driver. If no destFp specified will be in /drv/type/name.drv
# name="anynameHere"
name="RivFs_FAT32"
# Optional: Overrides the filepath automatically generated by name. Note that .drv will be added no matter what.
# destFp="fp"
destFp = "fat32"
# Version: version of the driver
# vers="MAJOR.MINOR ALPHA|BETA|STABLE"
vers="0.0 ALPHA"

[cfg]
# This should define all of the function names of the functions in a format RivOS expects. 
shouldactivatefn="shouldActivate"
# The rest of the functions are driver type specific.

# For fs:
[cfg.fs]
# Type of fs (E.G. ext4, btrfs, NTFS, FAT32 etc.)
# type="fsType"
type="fat32"

# What should happen if the driver aborts? Can also be LOG or CUSTOM_SIGNAL. 
# If abort=CUSTOM_SIGNAL a signalHandlr functionname should also be defined.
abort=FATAL
[expects.sysc]
# We expect the ABI RivOSDrvOpLive (stands for RivOSDriverOperandsLive)
# This defines what each number in eax means to the interrupt (for example 0=read or something similar).
abi="RivOSDrvOpLive"
int=0x30
# Version of the RivOS Driver module system. Currently at 1.0 ALPHA
vers="1.0 ALPHA"
[expects.drv]
# This is VERY driver specific. For an example, we will use a fs driver.

# Depends on a storage driver and a baseio driver (provided by the kernel). 
drvs=storage, baseio
# Requires storage driver, since a filesystem needs to read the disk.
req=storage
# baseio is optional, because it is only used for logging.
opt=baseio
# Can also be INFORM. FAKE means the function will just noop, while INFORM will tell you the driver is not loaded, but tell you such.
opthandlr=FAKE
[expects.drv.storage.base]
# Base definitons for a driver.

# Should be the same as expects.sysc.abi
abi="RivOSDrvOpLive"

# Lists functions required by the driver. 
functions=all
# Version does not matter to us.
vers=auto
[expects.drv.storage.custom]
# Driver specific fields.

# Expected arguments
readargs=sec, buf, size
writeargs=sec, buf, size
getdrivesargs=none
getmaxdriveamargs=none

# Custom field by a storage driver: which drive should be selected when loaded.
drivesel=auto

# We are going to skip baseio, because it's largely the same.
[expects.order]
# In which position it should be loaded.
pos=auto

[build.sourceFiles]
# We are using C++, because no other filetypes are supported:(
type="cpp"
list=main.cpp, file2.cpp, etc.
~~~
